# 智能开发团队实战：以 Review Agent 为重点

2026-10-10 扩展：固定看板作为 Review 子练习保留；最终产品开发改用 `--requirements` 的多文件生成、Docker 外部验收、版本审批和独立交付，详见 [新产品开发指南](product-development-guide.md)。本文其余内容记录原课堂设计范围。

本章用 MetaGPT 组织开发团队，重点实现 Review Agent。HTML 课件说明角色、输入和验收；VS Code 展示完整源码、模型调用、工具结果和生成文件。

## 范围与验收

任务看板提供新增任务、查询列表、修改状态和 SQLite 保存。首轮代码由讲师提供，标为教学 PR；产品与架构角色整理需求和设计，开发角色在评审退回后调用模型修复。团队使用 MetaGPT 的 Role / Action / Team 与消息订阅，正常流程按产物依赖推进，失败回退由宿主触发。

角色链：产品经理 → 架构师 → 开发者导入候选变更 → Reviewer → Tester → 交付门禁；不通过时将当前评审及真实测试结果发送给开发者，再发起全新评审与测试。Reviewer 有自己的职责指令和本轮上下文，代码修改与固定检查命令由宿主执行。

Reviewer 输入包含 base/head 内容摘要、统一 diff、带原始行号的变更文件、调用方、需求契约、固定测试及真实检查结果；缺失与截断显式声明。输出为 verdict、summary、findings；每条问题包含严重度、文件、行号范围、原文证据、影响、修复建议及验证方法。程序校验证据与字段，不把结构化输出当作内容正确性的保证。上下文不足输出 needs_context，不能通过。

门禁绑定候选文件和固定验收材料的内容哈希；修改使旧评审、旧测试及批准失效。代码明确限制修复轮次和模型调用；失败、超限与缺上下文不自动交付。持久化保存状态和待审批版本，另一进程显式 approve / reject 后核对哈希和固定验收；生产任务调度或 CI 审批还需要身份、权限与并发控制。

教学验证：buggy / clean / incomplete 三种输入；非法状态持久化是可复现缺陷；固定测试由讲师维护，开发角色只能提交 board.py，不能修改测试使其通过。基础合同测试无需 MetaGPT 和模型；框架集成使用 MetaGPT 0.8.2 独立 Python 3.11 环境，受控模型替身检查实际消息流，另执行真实模型演示并记录结果。

## 实施顺序

1. 固定教学 PR、需求、调用方与验收测试。
2. 构建上下文、执行工具、校验评审证据与版本门禁。
3. 接入 MetaGPT 角色、行动、消息订阅与已有模型网关，运行修复与复审。
4. 提供 VS Code 配置、持久审批命令、讲师手卡和可运行看板。
5. 替换实战章节、重建课件与讲稿，验证界面布局和真实执行。

本章讲解和运行共十五分钟，课程总时长由构建计算。深入接入团队 CI、评审规则校准与历史样本评估收在手卡中。
