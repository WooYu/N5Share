# AI Agent 零基础到精通：多Agent协同实训

版本：2026-10-04，可运行实训版。建议时长：3小时。

材料来源：`sources/01_标准化文档.md` 与 `sources/04_HTML演示文档.html`。本版围绕原材料的五种协作模式、开发团队、通信协议与安全主题展开，补充独立代码入口、运行命令、产出文件与验收方法。

## 1. 培训目标与课堂安排

适用对象：第一次接触Agent、需要理解协作流程并完成一次实操的业务人员和开发者。零基础学员先完成离线路线；具有Python经验的学员继续完成框架路线。

完成培训后，学员应能解释角色、状态、工具和路由的区别，运行一套协作流程，查看各角色的执行顺序，判断什么时候使用流水线、Supervisor或Swarm，并定位环境、模型、路由和终止条件方面的问题。

| 环节 | 时间 | 学员产出 |
|---|---|---|
| 基础概念与模式选型 | 15分钟 | 选型判断表 |
| 环境检查与首个离线实验 | 25分钟 | sequential.json 与 sequential.md |
| 五种协作模式对比 | 40分钟 | 五种模式的事件轨迹 |
| Python框架与真实模型 | 40分钟 | 安装记录、构图检查或真实输出 |
| 人工审批与调用限制 | 20分钟 | 暂停记录、循环终止记录 |
| MCP、安全与排错 | 25分钟 | 本地工具结果、安全检查结果 |
| 综合练习与验收 | 15分钟 | 一份报告及运行记录 |

讲师应在课前完成环境准备。网络不畅或账号未就绪时，课堂使用离线路线，不把安装依赖和创建账号占用的时间算作学员操作失败。

## 2. 先建立四个基本概念

**Agent**：围绕一个目标或角色使用模型进行判断，并可能调用工具的执行单元。真实Agent通常有自己的角色提示词和对话上下文。

**工具**：执行确定操作的函数，例如查询本地资料、保存报告、检查语法。工具返回的事实必须与它实际执行的操作一致。提示词里写“搜索互联网”并不会自动产生联网搜索能力。

**状态**：一次任务的共享数据，例如资料、提纲、草稿、消息列表、已完成角色和调用次数。只有明确传递的内容才能被下一个角色读取。

**路由**：决定下一个执行者的规则。路由可以是固定流程、模型选择、Supervisor分配或Agent主动交接。控制流的形状与模型能力是两个维度。

```text
输入任务 -> 调度或路由 -> 角色执行 -> 更新状态 -> 下一角色 -> 最终结果
                         |
                         +-> 工具执行 -> 返回真实结果
```

普通函数分工也可以完成流水线。多Agent的价值主要在于多个角色需要独立判断、聚焦不同上下文或动态协作；角色数量本身不是效果指标。

### 2.1 三层运行结果必须分清

| 层次 | 本版实现 | 能验证什么 | 不能验证什么 |
|---|---|---|---|
| 离线控制流 | Node.js，固定模拟输出 | 顺序、路由轨迹、文件保存、步数限制、审批门槛 | 模型推理质量、真实API、框架兼容性 |
| 真实角色推理 | Node.js + DeepSeek | 每个角色独立上下文、模型路由、真实报告、调用次数 | LangGraph / AutoGen 的接口兼容性 |
| 原框架实训 | Python + LangGraph / AutoGen / MCP | 对应框架的构图、工具调用、检查点、协议连接 | 不能仅凭构图成功证明任务正确完成 |

本机已运行离线控制流并通过自动检查。当前Python入口无法启动，网络也无法下载依赖；真实API与Python框架实验尚未验证。查看 `验证报告.md` 获取具体范围。

## 3. 环境准备：先确保有一个入口可运行

### 3.1 文件位置

本版所有命令，除特别说明外，都在 `multi-agent-training` 目录中执行。

```powershell
Set-Location -LiteralPath "E:\Code_Tool\AgentShare\N5Share\multi-agent-training"
```

文件夹名称含中文和空格时，用引号包住完整路径。不要在某个代码块后面继续猜测缺失的模型变量，实验的导入、模型初始化和入口已经放入独立文件。

### 3.2 离线路线：Node.js 22或更新版本

```powershell
node --version
node run.mjs --help
node run.mjs --mode sequential
```

不需要执行 `npm install`，不需要API Key。也可以双击 `一键离线演练.cmd`：它会运行五种模式、暂停的开发团队示例、安全示例和自动检查。

若 `node` 无法识别，先安装Node.js，再重新打开PowerShell。课堂机器建议使用同一个版本；本次实测版本为 `v22.23.2`。

### 3.3 Python路线：3.12或更新版本

Python路线需要可用的解释器和网络。先检查：

```powershell
python --version
```

若提示“系统无法访问此文件”，或打开应用商店，当前命令可能只是应用商店执行别名。安装可运行的Python发行版，重新打开终端并再次检查版本；有多个Python时，用实际解释器的完整路径执行后续命令。

创建项目虚拟环境并安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r .\python\requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

后续直接使用虚拟环境的解释器，不要求激活环境，也不要求修改PowerShell执行策略。

`requirements.txt` 使用兼容范围，**不是已经安装验证的精确版本锁**。代码保留原材料中的 `create_react_agent` 接口，某些LangGraph版本可能给出弃用警告；构图检查与真实调用仍需分别验证。安装与实验全部通过后，记录本机版本：

```powershell
.\.venv\Scripts\python.exe -m pip freeze > .\python\requirements.lock.local.txt
```

这个文件用于记录当前平台成功安装的版本；不要把它当作已验证的跨平台锁文件。如果安装失败，保留完整错误，先处理冲突或网络问题，不要一次性升级所有包。

### 3.4 真实模型的Key配置

Node.js真实模式读取PowerShell环境变量：

```powershell
$env:DEEPSEEK_API_KEY = "替换为自己的Key"
$env:DEEPSEEK_MODEL = "deepseek-chat"
node run.mjs --mode sequential --live
```

不要在共享屏幕中输入真实Key。也可以在操作系统环境变量中配置后重新打开终端。本版不会把Key写进结果文件。

Python可使用同一组环境变量，或者复制配置样例并在本机编辑：

```powershell
Copy-Item .\python\.env.example .\python\.env
notepad .\python\.env
```

填入Key后再运行实验。Node.js不读取这个 `.env` 文件。模型以 `deepseek-chat` 为默认值，其他型号的工具调用与结构化输出能力需要单独测试，不能根据模型名字直接判断。

```powershell
node run.mjs --mode sequential
```

控制台应出现以下顺序：

```text
Mode: sequential | Backend: offline-simulation
01 worker: researcher
02 worker: outline
03 worker: draft
04 worker: editor
05 worker: writer
06 worker: seo
Status: completed | model calls: 0
```

打开结果文件：

```powershell
Get-Content .\outputs\sequential.json -Encoding UTF8
Get-Content .\outputs\sequential.md -Encoding UTF8
```

观察JSON中的字段：

| 字段 | 意义 |
|---|---|
| `backend` | `offline-simulation`表示模拟；`deepseek-api`表示调用真实模型 |
| `status` | completed、awaiting_approval或step_limit |
| `events` | 工具调用、角色执行、路由选择、暂停的轨迹 |
| `results` | 每个角色的输出，便于追踪中间结果 |
| `modelCalls` | Node.js真实请求计数，离线为0 |
| `tokens` | API返回的输入与输出Token累计，离线为0 |
| `content` | 最后一个角色的输出，不代表内容已经人工审核 |

本地资料来自 `data/corpus.json`，只包含原材料的协作模式与工程注意事项。没有互联网搜索结果，没有市场规模或商业预测数字。离线内容会明确带有“离线模拟”标记。

**验收标准**：命令正常退出，状态为completed，两份文件存在，角色顺序正确，modelCalls为0，能找到source编号。学员能够说明这证明控制流工作正常，但没有证明模型推理质量。

## 5. 五种协作模式：运行同一个任务

### 5.1 Sequential Chain：固定流水线

```text
研究 -> 提纲 -> 草稿 -> 编辑 -> 最终报告 / SEO -> 结束
```

```powershell
node run.mjs --mode sequential --topic "客服知识库的Agent协作方案"
```

固定流水线通常适合步骤清楚的任务：它便于验收、成本更容易估计。Node.js离线角色输出是模拟文本；真实模式会把上游输出作为下游角色的输入。

Python对应实验：

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab sequential --check
.\.venv\Scripts\python.exe .\python\labs.py --lab sequential
```

Python流程沿用原材料的五个节点：research、outline、draft、editor、seo。research直接调用本地资料工具，后四个阶段调用模型。`--check` 只构建图，不调用API；实际执行的最终内容在 `outputs/python/sequential.json` 的 `seo_content` 中。

本版修正了原示例中“向模型发送搜索请求就等于搜索”的问题：研究阶段实际读取本地资料，并保留来源标识。

**练习**：改变topic，比较离线与真实输出。真实模型可能忽略引用要求，因此引用保留仍需人工验收。

### 5.2 Supervisor：中央调度

```text
                Supervisor
                /    |    \
       Researcher Analyst Writer
```

```powershell
node run.mjs --mode supervisor
node run.mjs --mode supervisor --live
```

离线调度固定选择researcher、analyst、writer。Node.js真实模式会让调度模型从尚未完成的角色中选择下一个角色，选择结果经过白名单校验，每个角色在这组调度中只执行一次，writer被约束在最后执行。它展示受约束的模型调度，并不实现LangGraph的全部能力。

Python对应实验：

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab supervisor --check
.\.venv\Scripts\python.exe .\python\labs.py --lab supervisor
```

Python使用 `create_supervisor` 和 `create_react_agent`。Worker分别获得本地搜索、输入统计、报告保存工具。`write_tool` 真正写入固定输出路径 `outputs/python/agent_report.md`。

**观察点**：研究员是否实际调用本地工具，分析员是否接收到有效资料，作者是否保存报告；Supervisor是否重复调度。Python设置的递归限制会阻止无限图循环，但不等于任务成功，也不等于精确Token预算。

**练习**：提出只需一次简单回答的任务，讨论增加三位Agent是否划算。

### 5.3 Hierarchical：Supervisor管理子团队

Node.js辅助演练使用研究团队与编辑团队，方便在同一报告任务中观察两层路由：

```text
Root Supervisor
  Research Team -> Researcher / Analyst
  Editorial Team -> Critic / Writer
```

```powershell
node run.mjs --mode hierarchical
```

查看events，区分root_supervisor的团队选择与子团队对Worker的选择。真实模式下，父层与子层的调度都需要模型调用，可能增加成本；某些选择顺序也可能不符合资料依赖，需要评估输出。如果研究团队最后执行，程序会再调用writer汇总最终报告。

Python对应原材料的技术、设计、QA组织结构：

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab hierarchical --check
.\.venv\Scripts\python.exe .\python\labs.py --lab hierarchical --topic "设计一个待办事项工具的教学方案"
```

两个子Supervisor明确命名为 `tech_supervisor` 和 `design_supervisor`，父图名为 `ceo_supervisor`。这补齐了原片段中子图命名不明确的问题。

本实验产出教学方案。code_tool返回固定代码样例，design_tool返回教学模板，QA的工具只检查语法；它们不代表自动开发了一个网站。

**验收标准**：父图能识别两个不同子团队，输出中有技术、设计和QA内容，并明确说明样例工具的能力边界。

### 5.4 Swarm：Agent主动交接

```text
Researcher -> Critic -> Writer -> END
                |
                +-> Researcher（需要补充证据时）
```

```powershell
node run.mjs --mode swarm
.\.venv\Scripts\python.exe .\python\labs.py --lab swarm --check
.\.venv\Scripts\python.exe .\python\labs.py --lab swarm
```

Python使用 `create_handoff_tool` 与 `create_swarm`。Agent名称与handoff目标大小写必须一致。Writer没有反向handoff工具，避免最终写作后继续无休止交接。

handoff不等于新建一个线程，也不等于自动并行。它表示控制权转交到另一个Agent；接收方能够读取什么上下文，需要看框架的状态传递。

**练习**：观察Critic何时要求Researcher补充资料，为什么Writer应具有明确的结束职责。故意循环练习放在Network实验中完成。

### 5.5 Network：自由路由需要约束

```text
Planner <-> Executor <-> Reviewer
   \_____________________/
           Router -> END
```

```powershell
node run.mjs --mode network
.\.venv\Scripts\python.exe .\python\labs.py --lab network --check
.\.venv\Scripts\python.exe .\python\labs.py --lab network --max-steps 8
```

Node.js角色名仍为researcher、critic、writer；Python沿用原材料的planner、executor、reviewer。两套代码是同类控制流演练，不应逐条比较它们的角色名称或输出格式。

Python中的三处修正值得重点讲解：

1. 路由通过Pydantic枚举与模型结构化输出产生，限制为planner、executor、reviewer或END，避免直接使用任意字符串作为节点名。
2. 消息列表使用 `add_messages`，而非简单 `operator.add`。Sub-Agent返回完整历史时，按消息ID合并，避免历史被重复累加。
3. `steps`由代码累加，到达工作预算会报错；不会把“超限”包装成“任务成功”。此外设置图递归限制，防止外层路由无限循环。

步数限制不是完成条件。一个任务可以在很少的步骤内结束却没有完成；验收仍需检查最终报告、证据和审查结果。

**故意失败实验，不需要账号**：

```powershell
node run.mjs --mode network --force-cycle --max-steps 4
```

预期退出码为2，JSON中status为step_limit，不生成表示成功的Markdown。它模拟researcher与critic反复交接，证明步数限制由执行代码落实。

## 6. 原材料中的工具，如何变为真实能力

原材料的通用工具以格式化字符串返回“搜索结果”“代码实现”“测试报告”。这些返回值适合展示接口形状，不能证明已经完成搜索、开发或测试。

本版 `python/common.py` 将六个工具的输入与真实行为写清：

| 工具 | 输入 | 实际行为 | 边界 |
|---|---|---|---|
| search_tool | query | 查询本地JSON资料，无匹配时返回完整资料并标明回退 | 不联网 |
| analyze_tool | data | 统计字符数及出现的source编号 | 不生成市场统计 |
| write_tool | content | 保存Markdown到固定输出路径 | 不接受任意文件路径 |
| design_tool | requirement | 返回明确标注的架构教学模板 | 不执行设计或部署 |
| code_tool | spec | 返回固定的待办事项函数样例 | 不是动态生成完整应用 |
| test_tool | code | 使用ast.parse检查Python语法 | 不执行代码、不运行单元测试 |

Node.js模式只在研究角色开始前由应用读取本地资料，没有通过API Function Calling让模型自主选择工具。需要学习真实工具调用的学员使用Python路线。

**练习**：给test_tool一个语法正确但业务逻辑错误的函数，解释为什么“syntax_valid=true”不能代表“业务测试通过”。随后讨论如何增加真实单元测试工具，而不是修改提示词声称已经执行测试。

## 7. 开发团队与人工审批

本版沿用产品经理、架构师、前端、后端、审查员和测试工程师六个角色。

```text
PM -> Architect -> Frontend -> Backend -> Reviewer -> 人工审批 -> Tester
```

前端与后端在本实验中顺序执行。不要把组织图中的并列角色误认为程序已经并行运行。

### 7.1 先观察暂停

```powershell
node run.mjs --mode devteam
```

预期status为awaiting_approval，events中有reviewer和interrupt，没有tester，也不生成成功版devteam.md。

审核后显式允许测试角色：

```powershell
node run.mjs --mode devteam --approve
```

Node.js这个命令会重新执行整条流程；它是审批门槛演练，没有持久化检查点。若用于真实模式，重新执行前序角色会再次消耗模型额度。

### 7.2 Python检查点恢复

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab devteam --check
.\.venv\Scripts\python.exe .\python\labs.py --lab devteam --topic "设计待办事项工具的教学方案"
```

reviewer被放在外层StateGraph中，`interrupt_after=["reviewer"]`指向真实存在的外层节点。运行后检查 `pending_nodes`，预期包含tester。

原材料将暂停放在Supervisor图上，是否生效取决于编译后的图中有没有同名节点。本版用显式外层节点保证暂停位置可检查。

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab devteam --approve --topic "设计待办事项工具的教学方案"
```

这个命令在一次进程内先执行到reviewer，再带相同thread_id调用 `invoke(None)` 恢复tester。默认不自动恢复；调用者必须明确传入approve。

`InMemorySaver`只保存在当前进程内。先运行一次、不传approve，然后关闭进程，再另起命令，不会读取旧检查点。生产中的跨进程审批需要持久化存储、待审批任务ID和审批记录，本版没有实现这些。

提示词里写“最多重试3次”不是重试限制。原材料的MAX_RETRIES仅进入提示词；本版不宣称它已经成为执行层重试机制。若要实现审查失败后的自动返工，应增加显式计数状态和条件边，达到上限时以失败状态停止。

**验收标准**：审批前tester未运行；显式批准后tester运行；能说明内存检查点的生命周期，以及测试计划、语法检查和真实业务测试的区别。

## 8. AutoGen：轮询讨论与自主交接的区别

```powershell
.\.venv\Scripts\python.exe .\python\labs.py --lab autogen --check
.\.venv\Scripts\python.exe .\python\labs.py --lab autogen --max-turns 3
```

本版采用AgentChat API风格的 `RoundRobinGroupChat`，三位角色依次发言。max_turns由框架限制轮数，模型客户端在finally中关闭。

异步Console接收 `team.run_stream(...)`；不是把 `team.run(...)` 返回的协程直接传给Console。需要先验证本机安装的AutoGen版本，依赖范围尚未在当前机器安装实测。

轮询式讨论的顺序由团队机制决定，不能称为Agent自主handoff。SelectorGroupChat可以通过模型或选择器决定下一位发言者；若要使用特定版本的Swarm团队或跨团队交接，需要按该版本API单独实现。本版不把“选择发言者”与全部Swarm语义划等号。

**验收标准**：三位角色按照顺序发言，stop_reason有停止原因，`outputs/python/autogen.json`包含消息。内容仍然需要评审。

## 9. A2A与MCP：先理解边界，再连接工具

| 维度 | A2A | MCP |

| 教学用途 | 理解跨框架任务协作 | 实际连接本地资料工具 |

原材料的Agent Card JSON用于展示“能力名片”。版本号、参与组织数量、字段名、发现路径与认证规范会变化；本版没有在线核验，不将这些静态信息作为当前协议保证，也不把原JSON作为可直接部署的接口规范。

### 9.1 MCP本地实验，不需要模型Key

已安装Python依赖后：

```powershell
.\.venv\Scripts\python.exe .\python\mcp_client.py
```

客户端会自动启动 `mcp_server.py` 子进程，用stdio连接并完成初始化，不需要另开服务终端。

预期输出包含：

```text
TOOLS: ['search_local']
TOOL RESULT: ... Supervisor ...

```

## 10. 安全、预算与失败演练

结构化消息只能让字段更容易校验，不能自动消除提示词注入。工具白名单只有在真实执行工具前由应用校验，才具有执行约束。

```powershell
node run.mjs --mode security
```

预期 `outputs/security.json` 中三项checks均为true：合法工具请求允许，未经授权的delete_files请求拒绝，超过预算的请求拒绝。

本实验是独立校验练习，没有实现消息数字签名、身份验证、数据分级或完整注入防御。不要把练习通过表述为生产安全认证。

真实模型实验的限制：

| 限制 | Node.js | Python |
|---|---|---|
| 单次请求超时 | 45秒 | 45秒 |
| 单次输出上限 | 600 tokens | 600 tokens |
| 自动API重试 | 无额外自动重试 | max_retries=0 |
| Worker限制 | --max-steps，默认12 | Network默认8个Worker步骤 |
| 请求次数 | --max-calls，默认24 | 没有统一全局API次数计数器 |
| 图循环限制 | Worker次数约束 | --recursion-limit，默认60 |
| Token记录 | API实际usage累计 | 本版未统一采集各框架usage |

Node.js不会在一次请求完成前预知实际Token消耗，所以max-calls和max_tokens只能限制请求规模，不能当作精确金额预算。Python图递归次数与真实请求次数也不是一一对应。

观察终止限制：

```powershell
node run.mjs --mode sequential --max-steps 2
node run.mjs --mode network --force-cycle --max-steps 4
```

预期均以step_limit停止，退出码为2。退出码0表示演练按预期结束或按设计暂停；退出码1表示配置或运行错误；退出码2表示达到执行上限。判断完成情况必须同时检查status。

真实模式遇到HTTP 401检查Key；429检查配额或请求速率；连接错误检查网络；超时检查服务响应。不要把异常包装为“已成功生成”。

## 11. 常见问题与定位顺序

| 现象 | 原因方向 | 操作 |
|---|---|---|
| node无法识别 | 未安装或PATH未更新 | 安装后重新打开终端，再查node --version |
| Python启动应用商店或拒绝启动 | 执行别名不是可用解释器 | 安装实际解释器，使用完整路径 |
| pip安装失败 | 无网络、代理、依赖冲突 | 保留第一条错误，检查网络和Python版本 |
| ModuleNotFoundError | 装包环境与运行环境不同 | 所有安装和运行均用.venv解释器 |
| 缺少DEEPSEEK_API_KEY | Key未传入当前进程 | 检查配置位置，不输出Key值 |
| GraphRecursionError | 重复调度或handoff无终点 | 检查最后几条消息、路由与结束条件 |
| 节点名称冲突 | 多个子图名称相同 | 检查tech_supervisor和design_supervisor名称 |
| 消息越来越长 | 历史重复累计或缺少摘要 | 检查add_messages和消息ID；减少不必要历史 |
| reviewer后仍自动运行tester | 暂停节点不在当前图或代码自动恢复 | 检查外层节点名和是否传入approve |
| MCP解析失败 | 服务端stdout混入日志 | 将日志转到stderr，使用客户端自动启动 |
| 语法检查通过但应用有错 | 没有执行业务测试 | 增加真实测试环境与用例，不能仅看syntax_valid |

定位顺序：先解释器与路径，再依赖，再配置和网络，最后检查图结构、工具行为与模型输出。一次只改一个已确认的问题，并复现原命令。

## 12. 综合练习：为一个业务任务选择协作方式

选择“客服知识库维护”或“企业培训报告编写”，使用本地资料完成一次演练：

```powershell
node run.mjs --mode supervisor --topic "企业培训报告的Agent协作方案" --output .\outputs\exercise
```

账号和网络就绪后，可以增加真实模型对照：

```powershell
node run.mjs --mode supervisor --topic "企业培训报告的Agent协作方案" --output .\outputs\exercise-live --live --max-calls 12
```

每位学员提交以下结果：

1. 输出JSON与报告Markdown，并注明是离线模拟还是真实模型。
2. 一段执行轨迹，指出调度者、Worker和工具的区别。
3. 选择这种模式的理由，以及使用更简单流水线是否足够。
4. 一次失败演练记录，说明超限、暂停与错误的差异。
5. 真实模型学员补充调用次数、Token记录、内容评审及事实核对。

| 验收项 | 通过条件 |
|---|---|
| 能启动 | 命令、环境与所用入口写清楚 |
| 能追踪 | 找到每个角色和路由的记录 |
| 能产出 | 状态与文件一致，来源可追溯 |
| 能停止 | 循环实验能终止，审批前测试角色不运行 |
| 能解释 | 不把离线模拟、构图成功或语法检查误认为真实业务成功 |

模型输出没有天然正确性。验收应包含任务是否完成、来源是否可信、角色是否重复、费用是否合理，而不是只看“有一份报告”。
