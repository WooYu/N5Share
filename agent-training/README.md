## 现场运行双 Agent Demo

需要 Python 3.10 或更新版本，仅使用标准库。终端进入解压后的 `agent-training` 目录：

```powershell
python demo/server.py
```

打开 <http://127.0.0.1:8765>，按 O 跳到第 29 页，点击“运行 Python Demo”。勾选“注入一次字段错误”观察失败修正。页面在 Python 运行结束后展示可逐步播放的轨迹，并非实时 token 流。

若 8765 端口占用：

```powershell
python demo/server.py --port 8766
```

浏览器相应打开 <http://127.0.0.1:8766>。服务仅监听本机，停止时在终端按 Ctrl+C。不要使用普通 `python -m http.server` 代替本服务，因为它没有 `/api/run` 接口。

也可直接在终端运行：

```powershell
# 正常路径
python demo/agents.py

# 人为注入一次字段错误，触发反思与修订
python demo/agents.py --inject-failure

# 预算耗尽：预期退出码 1，状态 stopped
python demo/agents.py --max-steps 1

# 单元测试
python -m unittest discover -s demo -v
```

每次命令行运行在 `demo/output` 生成独立的 `<run_id>-trace.json`。成功运行另生成 `<run_id>-report.md`；失败或停止不生成成功报告。把轨迹拖选到第 29 页的“导入轨迹”，即可讲解命令行运行结果。

### 三种展示状态必须区分

| 入口 | 实际发生什么 |
| --- | --- |
| 运行 Python Demo | 本次真正执行本地 Python 与 CSV 工具，模型决策由规则模拟 |
| 加载教学回放 | 播放构建演示稿时已运行并验证的历史轨迹，不执行新的任务 |
| 导入轨迹 | 展示所选 JSON 文件的历史记录，不重新执行或证明文件声明的结果 |

### 真实本地模型模式（可选）

代码还提供 Ollama `/api/chat` 适配器，可让两个角色分别调用真实本地模型。需要自行已有运行中的 Ollama 服务和已安装模型；本次交付环境未安装 Ollama，因此**此模式未做真实模型端到端验证**。没有调用 OpenAI API，也没有创建、写入或使用任何 API 密钥。

1. 从 [Ollama 官方站](https://ollama.com/)准备本地服务，使用 `ollama list` 查看已有模型的准确名称。
2. 指定实际安装的模型，例如已安装 `qwen2.5:7b` 时：

```powershell
python demo/agents.py --mode ollama --model qwen2.5:7b --inject-failure --max-steps 8
```

上面的模型名只是一个条件性示例，命令不会自动下载模型；必须换成 `ollama list` 中实际存在的名称。适配器固定连接本机 `http://127.0.0.1:11434/api/chat`，使用 JSON 输出。两个角色的指令、上下文和调用分开，但可以使用同一个底层模型。

3. 将生成的 JSON 轨迹导入第 29 页。页面会标注为 Ollama 模型模式。

教学约束：规划者在既定 S1→S2→S3 依赖骨架内生成目标与验收条件；执行者在三个白名单工具中选择对应调用。故障开关人为改写一次汇总参数，不能解读为模型自然犯错。模型格式不合格、连接失败或超时都会进入失败状态，**不会暗中回退为模拟成功**。单次模型请求最多等待 45 秒，轮次默认最多 8 次；总时间在步骤边界检查，超过 180 秒后停止，在途请求可能额外等待最多一个请求超时。

## 15 分钟现场演示脚本

1. **0–2 分钟：给任务与验收。** 打开 `demo/orders.csv`，解释 completed、gross、refund。说明它是合成数据。
2. **2–4 分钟：展示职责边界。** 规划者产出步骤，执行者选工具，宿主程序写状态，校验器判定成功。说明当前是模拟决策还是真实 Ollama 模式。
3. **4–8 分钟：运行故障路径。** 点击运行，逐事件播放；停在字段 sales 报错处，先请学员判断如何修正，再看 Reflexion 和 Plan v2。
4. **8–11 分钟：看结果与证据。** Finish 中 verified=true，总额、品类、订单 ID 可复核。下载 JSON 或打开命令行输出。
5. **11–13 分钟：对比正常路径。** 取消故障勾选再运行；观察没有反思和重规划。演示轮次上限导致 stopped。
6. **13–15 分钟：复盘。** 模型承担什么、程序保障什么、多角色增加了哪些成本？讨论换成真实业务时需要添加的能力。

## 代码阅读路线

| 文件或入口 | 用途 |
| --- | --- |
| `demo/agents.py` → `PlannerAgent.plan()` | 初始计划；从失败反馈生成反思与剩余计划 |
| `ExecutorAgent.decide()` | 根据当前步骤、schema 和上下文提出动作 |
| `ToolBox.call()` | 三个工具的参数校验和真实 CSV 计算 |
| `run()` | Thought / Action / Observation、计划版本、预算、错误与终止 |
| `verify()` | 用独立的整数分计算路径核对总额、品类、订单证据 |
| `LocalModel.ask()` | 可选 Ollama 本地真实推理，严格解析 JSON |
| `demo/server.py` | 本地 HTML 服务和现场运行接口 |
| `content.py` | 全部 32 页正文与讲师备注，可直接编辑 |
| `template.html` | 页面样式、翻页、交互与轨迹播放器 |
| `build.py` | 将内容和已验证样本轨迹嵌入独立 HTML |

修改课程后运行 `python build.py`，会更新 `index.html`、`speaker-notes.md` 和样本轨迹。不需要 Node.js 构建依赖。双角色使用串行编排，反思记忆只属于一次运行；事件保存的是独立快照，不会随后续计划修改而改变。本 Demo 不包含生产级并发一致性、数据库检查点恢复或费用统计。

## 课后练习与参考思路

**练习 A：地区维度（15–20 分钟）**

增加 `region` 字段，将 O001/O002/O004 设为华东，其余已完成订单设为华南。按地区计算净额，并保持原过滤口径。预期华东 1650，华南 1000，总计仍为 2650。

参考步骤：给工具 schema 加 `group_by` 枚举；让计划说明按地区汇总的验收条件；返回每组订单 ID；校验器独立复算。故意传 `area` 验证错误，再依据 schema 修正。不需要为了增加一个维度再增加 Agent。

**练习 B：工具暂时失败（10 分钟）**

让只读 inspect 在第一次调用时返回临时故障。区分可重试的临时错误与不可原样重试的字段错误。预期有限重试后成功；永久失败时受控停止，不产出成功报告。

**练习 C：迁移到 LangGraph（30 分钟）**

定义 State 字段：plan、plan_version、observations、memory、status。把 planner / executor / validator 映射为节点，错误边回 planner，完成边到 END。生产恢复另需 checkpointer、稳定 thread_id 和工具幂等；不要把保存 trace.json 视为支持断点续跑。

## 常见问题

- **Python 命令不存在：** 安装 Python 3.10+，Windows 也可用 `py` 代替 `python`。可先运行 `python --version` 检查。
- **直接打开 HTML 时运行按钮提示启动服务：** 属于预期行为；静态文件不能执行本地 Python。回放无需服务。
- **Ollama 模式失败：** 检查服务、模型名与 JSON 输出能力；阅读最后一个 Stop 事件。不要将失败解释成完成。
- **中文终端显示乱码：** 脚本将标准输出设为 UTF-8，建议使用 Windows Terminal；输出文件均为 UTF-8。
- **想改页数或时长：** 编辑 `content.py` 和课程议程后重新构建；当前末尾有 32 页断言，变更页数时同步调整。
- **框架信息过时：** 开课前查看 `sources.md`。2026-09-10 核对时 AutoGen 官方已标注维护模式，并建议新项目评估 Microsoft Agent Framework。

完整讲稿见 `speaker-notes.md`，参考资料见 `sources.md`。
