七种架构详解（1/2）

1

单 Agent 架构

(Single Agent)

最基础的架构，一个大模型负责所有决策

特点
  • 一个大模型负责所有决策
  • 可调用 tools / API / DB
  • 有简单 memory
优点
  • 简单直接
  • 成本低
问题
  • 思考爆炸
  • 上下文污染严重
  • 不适合复杂任务
适用场景
CopilotChatGPT简单自动化助手
2

ReAct 架构

（推理 + 行动）

经典 Agent 范式：Reason + Act 循环

特点
  • 强调链式推理，可解释性强
  • 动态调用工具，处理多步骤任务
优点
  • 适合反馈驱动的探索
问题
  • 调用与延迟增加
  • 可能跑偏或无进展
  • 需限制轮次并校验结果
适用场景
复杂问答多步骤任务探索阶段
3

Plan & Execute 架构

（规划执行）

先规划，再执行，更工程化的版本

特点
  • 先生成完整计划，再逐步执行
  • 稳定性更高，适合复杂任务
优点
  • 稳定性更高
  • 适合复杂任务（代码生成/自动化）
问题
  • 初始计划可能有遗漏
  • 条件变化时需反馈与重规划
适用场景
代码生成项目自动化长流程任务
4

多 Agent 架构

(Multi-Agent)

多个 Agent 分工协作，各司其职

特点
  • 任务拆解清晰，降低上下文污染
  • 可扩展性强
优点
  • 降低复杂度
  • 易于扩展和维护
问题
  • 成本高
  • 协调复杂
适用场景
团队协作复杂项目企业级应用

七种架构详解（2/2）

5

Router + Skill 架构

先识别意图，再加载适合的技能

特点
  • 极强稳定性（不靠推理）
  • 可控（企业级必备）
  • 可缓存（性能高）
  • 易评估（命中率）
适用场景
CopilotAI Coding技能系统
问题
  • Skill 设计成本高
  • 命中冲突
  • 协调复杂

Skill 本质：可执行能力（Skill）+ 知识说明（Reference）

6

Blackboard 架构

（黑板系统）

多 Agent 共享状态，通过状态驱动执行

特点
  • 所有 Agent 共享上下文
  • 通过状态变化驱动执行
  • 适合复杂协作场景
问题
  • 状态管理复杂
  • 不易追溯问题
代表
LangGraph工作流引擎分布式系统
7

Graph / Workflow 架构

（企业级主流）

显式编排依赖、分支、并行与反馈回路

特点
  • DAG 流程，支持条件分支、并行执行
  • 可回溯、可观测、可重试
  • 企业级稳定性，高可扩展
优势
  • 企业级稳定
  • 可 Debug
  • 支持长流程

                顺序、并行与反馈回路

                基本结构依赖关系典型用途
