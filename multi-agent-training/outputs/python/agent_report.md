# 多智能体协作模式对比简报

## 一、背景与判断标准

多智能体并非默认选项。每个真实 Agent 都拥有独立的模型上下文与角色提示词，固定函数分工并不等于自主 Agent；是否需要多 Agent，应依据任务复杂度与成本来判断（source-01）。当步骤确定时，可采用工作流而非自主调度（source-05）。

## 二、主要协作模式

**1. Supervisor（中央调度）**
由中央调度 Agent 分配任务，Worker 执行后汇报，适用于动态分发与结果整合；但中心节点可能形成调度瓶颈（source-02）。

**2. Hierarchical（分层调度）**
由多层 Supervisor 管理多个子团队。编译后的子图应具有唯一名称，顶层才能区分不同子团队（source-03）。

**3. Swarm（自主交接）**
Agent 通过 Handoff 主动交接控制权，没有统一中央调度；必须设置退出条件与调用上限。需注意，轮询式讨论并不等于自主交接（source-04）。

**4. Network（对等路由）**
对等 Agent 可自由路由。路由结果需要校验，消息要正确合并，并设置步数或递归限制，以防止无限循环（source-06）。

**5. Sequential Chain（固定顺序）**
研究、提纲、草稿、编辑与 SEO 按固定顺序执行。步骤确定时可采用工作流，未必需要自主调度（source-05）。

## 三、对比维度

| 维度 | Supervisor | Hierarchical | Swarm | Network | Sequential Chain |
|---|---|---|---|---|---|
| 控制拓扑 | 中心化（source-02） | 多层中心化（source-03） | 去中心化（source-04） | 去中心化（source-06） | 固定流水线（source-05） |
| 自主程度 | 中央分配 | 分层分配 | 自主交接 | 自由路由 | 确定性执行 |
| 主要风险 | 调度瓶颈（source-02） | 子图命名与身份（source-03） | 缺少退出条件（source-04） | 无限循环（source-06） | 灵活性不足（source-05） |

## 四、协议与安全

A2A 连接 Agent 与 Agent，MCP 连接应用与工具或数据。工具白名单、超时与预算检查需要由执行代码落实；结构化消息并不能保证防止提示词注入（source-07）。

## 五、结论

模式选择应回到任务复杂度与成本（source-01）：步骤确定时优先采用固定工作流（source-05）；需要动态分发与结果整合时采用 Supervisor（source-02），规模扩大时演进为 Hierarchical（source-03）；需要自主交接或自由路由时采用 Swarm 或 Network，但必须设置退出条件、调用上限与递归限制（source-04、source-06）。无论采用何种模式，协议与执行层的安全约束都不可省略（source-07）。

本地来源中不含市场统计数据或量化基准，本简报仅作定性模式对比，未引入任何虚构数据。
