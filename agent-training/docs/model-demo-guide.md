# 七种架构：大模型课堂演示指南

本章用同一组出游需求对比七种架构。第 06 至 12 页按前面架构地图的①至⑦排列：单 Agent、ReAct、规划执行、多 Agent、Router + Skill、Blackboard、Graph / Workflow。LLM、RAG 和工具属于①的组合能力，Reflexion 属于③的反馈机制。本指南用于第 06 至 12 页的真实模型演示，计入本章 20 分 50 秒，不额外加时。

第 06 至 12 页均有真实模型入口，对应①单角色检索与工具、②ReAct、③规划执行与Reflexion、④主管 / 层次化 / Swarm、⑤关键词 Router 与模型执行技能、⑥黑板触发模型角色、⑦显式图与模型结果节点。所有“下一步演示”均为离线规则示意。图中橙色「!」标出局限位置，经过对应节点与信息流时突出显示。

七页离线演示分别设置不同事件：①先想到公园后查到雨天，②310元超额后改查210元，③执行途中预算300→200元，④天气与费用角色给出不同局部建议，⑤用户改成只算费用，⑥费用角色等待名单，⑦雨天200元走无解出口。真实入口仍使用“更多”中的初始参数，不自动重放离线事件；③真实模式沿用下文的漏餐费草稿反馈示例，⑤真实模式处理当前初始需求。第 12 页初始预算为200元，可改成300元观察成功分支。

## 启动与使用

1. 安装本项目 `requirements.txt`，配置 DeepSeek 环境变量或复用本机已有受保护凭据。
2. OpenAI 备用沿用 CCSwitch 当前 Codex 供应商与官方 `codex` 客户端（已用 0.154.0 验证）。服务只读配置，不修改或复制密钥到仓库。
3. 双击 `start-demo.cmd`，或运行 `python demo/server.py`，打开 `http://127.0.0.1:8765`。
4. 到第 06 至 12 页打开“更多”，选择天气、预算，点击“真实模型演示”。第 09 页的真实运行窗口还可选择协作模式；第 10 页先选用户需求，真实运行使用相同意图。
5. 点击“开始真实运行”，查看模型请求、决策摘要、实际工具结果和角色消息。可停止、回看或导出本次轨迹。

真实窗口按架构、天气、预算、协作模式、Router 用户需求分别保存轨迹。切换页面始终显示该页配置；其他页的运行不会填入当前事件列表。服务同时只允许一个运行，后台任务会显示来源，并提供明确的停止按钮；等待停止后再开始当前页。重新开始同一配置会清空旧事件并产生新的运行ID；回到同一配置可查看它自己的上一条轨迹。

直接双击 HTML 只支持离线示意。运行窗口显示当前供应商与模型；点击开始才产生模型用量。Windows 下将本次客户端及其子进程纳入独立进程范围，停止或超时时统一清理。单次最多 12 次模型调用、20 次工具调用、8 分钟，每个模型请求最多 90 秒；同一服务同时只运行一个真实任务。关闭窗口不会取消任务，需使用“停止运行”。运行记录保存在服务内存中，最多保留 8 次；需要留存时导出 JSON，重启服务不保留历史。

DeepSeek 直接使用官方 Chat Completions 接口。OpenAI 备用复用 CCSwitch 当前选择的 Codex 连接；该连接要求官方客户端，因此使用 `codex exec` 及结构化输出。CCSwitch 改选供应商后，下次新运行重新读取配置；本次切换到备用后继续使用备用。

此模式使用**结构化行动协议**：模型返回 `calls` 中的工具名称与参数，由课堂宿主执行白名单工具，并把观察结果交给下一次模型调用。请求使用本课 JSON 行动格式，由宿主解析执行。每次课堂调用关闭插件同步、命令执行工具与子 Agent 功能，模型处理隔离的课堂提示；角色协作由本地演示程序组织。各角色可以共用同一个模型，分别调用并拥有各自上下文。

模型费用按供应商规则计算。页面显示客户端报告的 token 数，不估算价格。场馆、天气与费用仍为合成资料，真实的是模型调用、程序计算与角色间交付。

## DeepSeek 主配置与 OpenAI 备用

默认使用 DeepSeek 官方接口的 `deepseek-flash`。连接失败、认证或额度异常、限流、超时时，切换到 CCSwitch 当前 OpenAI/Codex 连接，保留已有计划、角色消息和工具证据；本次后续调用继续使用备用。启动时 DeepSeek 未配置且备用可用时，直接使用备用并记录原因。

切换会在运行窗口和导出轨迹中明确显示。失败尝试与备用请求都计入每次 12 次模型调用的总上限，整体仍受 8 分钟限制；主动取消、结构化输出不合格和业务验收不通过不会触发备用重试。备用自身也失败时停止并保留记录，不继续循环切换。

Windows 凭据通过当前用户的 DPAPI 加密，保存在 `%LOCALAPPDATA%/N5AI/deepseek.key.dpapi`，不在代码仓库与培训包中。换电脑或换 Windows 用户需重新配置；也支持进程环境变量 `DEEPSEEK_API_KEY`。新副本没有 DeepSeek 凭据时，可使用已配置的 OpenAI 备用和离线示意。浏览器只收到供应商、模型与配置状态，不接收密钥。

DeepSeek 采用官方 Chat Completions 接口、JSON 输出和非思考模式，返回仍经过同一套结构校验。参考：[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode)、[模型列表与说明](https://api-docs.deepseek.com/quick_start/pricing)。

## 统一任务与资料

每种机制使用一个新会话，或显式清空上一次尝试的记忆，避免提前带入后续阶段的证据。各阶段沿用相同预算和资料口径。推荐先演示雨天、300 元，再把预算改为 200 元验证无解时能否停止。

```text
任务：为两名成人和一名儿童安排周六半日出游，总预算300元。
只提供建议，不预约、不付款。不知道的事实标为待核实。
费用包含三人的门票、交通和餐费，不能自行调高预算。
输出候选方案、完整费用、资料引用和仍需确认的事项。
```

以下全部为课程合成资料，不表示实时天气、营业情况或真实报价：

| 来源 | 内容 |
| --- | --- |
| WX01 | 周六下雨，需选择室内活动 |
| D01 | 雨天排除户外场馆 |
| D02 | 总价必须包含门票、交通、餐费 |
| P01 | 湖畔公园，户外，60 + 40 + 80 = 180 元 |
| P02 | 自然馆，室内，150 + 60 + 100 = 310 元 |
| P03 | 城市博物馆，室内，90 + 40 + 80 = 210 元 |

300 元雨天有城市博物馆这一可行候选；200 元雨天没有可行候选。验收检查依据这些条件，模型输出的措辞和调用顺序可以不同。

## 第 6 页演示：单 Agent 的 LLM、RAG 与工具能力

页面以同一 Agent 连接 RAG 文档库和工具宿主的结构图为主体。按“开始演示 / 下一步”分别高亮检索请求、文档返回、工具请求和工具返回，底部常驻优势、局限和适用场景。“更多”包含完整记录、“跳到 RAG / Tool”和真实模型入口。真实模型入口先关键词检索本地资料，把命中文档放入模型上下文，再由同一角色提出一批工具请求，依据返回生成带引用的建议。下面的纯生成说明可用于讲师补充讲解。

**LLM：** 只给任务，不提供资料。观察模型是否主动指出缺少天气和费用依据。模型可能建议核实资料，不能为了演示而声称它一定会编造事实。

**RAG：** 程序从本地三条资料按关键词检索，将命中的 D01、D02 和编号提供给模型，要求“仅根据命中资料回答，逐条引用来源，区分已知规则和待查事实”。直接把资料粘贴到聊天窗口能展示参考资料回答，但应称为“人工提供检索结果”，不能称为已经运行了检索服务。

**Tool Calling：** 本地运行环境已提供 `read_weather()`、`read_catalog()`、`calculate_cost(place_id)` 三个只读工具。模型一次提出一批结构化工具请求，程序真实执行后交给模型汇总。天气与场馆返回上述固定资料，成本由程序相加。投影显示工具名称、参数、实际返回值和最终引用。模型提出调用请求，宿主程序校验参数并执行；模型自己输出一段工具 JSON 不代表工具已经执行。

## 第 7 页演示：ReAct 推理范式

```text
根据任务和当前已获得的观察，每轮只选择一个下一步行动。
给出一句简短决策摘要，选择一个允许的工具，等待工具结果后再继续。
根据结果选择下一个行动，或给出最终建议。
无可行方案时说明依据并停止，不能改动预算或省略费用。
不需要展示内部思维过程。
```

演示 **Thought → Action → Observation → 下一轮 Thought**：Thought 在界面中只展示简短的决策摘要；Action 是模型提出的工具请求；Observation 是宿主执行后的返回。重点观察模型是否使用最新的工具结果改变后续行动。

真实 ReAct每轮只允许一个工具请求，宿主返回实际观察后模型才决定下一步；批量请求会停止并说明原因。模型可能直接选择博物馆，也可能先尝试310元的自然馆，不能要求固定候选顺序。离线示意固定展示超预算后换候选。每次工具返回保留来源，程序硬上限为12次模型调用和20次工具调用；超时、失败或无进展必须有限停止。

若只用聊天界面，可由讲师人工回填工具结果来演示这个交互协议，现场标注“真实模型生成，工具结果由讲师提供”，不要称为自动 ReAct 系统。

## 第 8 页演示：Plan-and-Execute + Reflexion

先让模型规划：

```text
先输出计划v1，每项包含任务、依赖、所需工具、产物和验收条件。
现在不要给出出游结论。计划确认后，按依赖执行并保存证据来源。
```

为稳定展示失败反馈，讲师注入一份明确标注为“教学错误样本”的执行结果：

```text
计划v1的待验收草稿：去湖畔公园，门票60元加交通40元，共100元。
实际证据：周六下雨[WX01]；公园为户外[P01]；餐费80元[P01]。
检查草稿，输出失败项、证据和下一次应采取的具体动作。
把反思记录加入后续尝试的上下文，输出计划v2。
保留有效证据，只重做受影响步骤，然后重新验收。
```

投影依次展示：计划v1、首次执行的实际天气/场馆名单/公园费用、教学错误草稿、程序验收反馈、反思、计划v2、Executor再执行与验收。首次工具观察保留在v2上下文。Reflexion把“漏餐费、天气不符”转成具体修改动作，不只是润色，也不更新模型权重。

雨天 300 元下可以修订为城市博物馆 210 元；雨天 200 元下应报告无解。当前模式展示一次计划 v2 修订，程序验收预算、费用完整性、天气适配和引用。模型自称通过不能代替验收。

## 第 9 页演示：多 Agent 协作模式

| 模式 | 控制权与分工 | 同一个出游任务 |
| --- | --- | --- |
| Supervisor | 主管集中分派，收集产物并决定下一步 | 主管把天气检查和费用核算交给两个角色，再汇总 |
| 层次化 | 总主管委派给组长，组长再管理子角色 | 总主管管理出游组与预算组，各组内部拆任务 |
| Swarm | 当前角色根据需要将任务和控制权交接给其他角色 | 天气角色发现室内约束，交接费用角色，再交接汇总角色 |

Supervisor 可以构成层次化系统的一层。Swarm 在本课指动态交接的协作方式，不指某个产品 SDK；并行与评审可以组合进这些模式。

三种模式均可选择，分别保存轨迹。建议只现场跑Supervisor，其余用相同任务比较控制权，控制本章20分50秒节奏。层次化组长实际调用模型汇总子角色结果后交总主管；Swarm检查交接目标与完成角色，拒绝重复交接。角色上下文隔离，可以共用同一个底层模型：

- 天气角色：读取 WX01、D01 及场馆室内外属性，只交付天气限制和来源。
- 费用角色：读取场馆费用和 D02，交付完整总价及预算判断。
- 主管：分派任务，合并消息与共享状态，核对交集、证据和结束条件。

**Agent 间通信**使用明确消息，而非要求接收方猜测上下文：

```json
{
  "task_id": "outing-1",
  "from": "weather_agent",
  "to": "supervisor",
  "type": "result",
  "plan_version": 1,
  "summary": "雨天仅保留室内候选",
  "evidence_refs": ["WX01", "D01", "P02", "P03"]
}
```

**共享状态**与单条消息分开维护：

```json
{
  "task_id": "outing-1",
  "constraints": {"budget": 300, "booking_allowed": false},
  "plan_version": 1,
  "observations": {"weather_agent": {}, "cost_agent": {}},
  "pending_roles": ["weather_agent", "cost_agent"],
  "draft": null,
  "status": "running"
}
```

协调器校验消息的任务 ID、来源、计划版本，再分别合并各角色证据。两份必要结果齐备后才能汇总，旧版本不能覆盖新证据。任何角色失败都要记录，缺关键证据时停止或请求人工补充。Swarm 还要约束允许的交接对象、交接次数和最终出口，防止循环转交。

单次提示词让一个模型扮演三个角色，只能称为“角色协作示意”。真实多 Agent 需要分别调用角色、隔离上下文，并实际维护消息与状态。

## 第 10 页演示：Router + Skill

先在“更多”选用户需求，再打开真实窗口。路由与模拟使用同一输入文本和关键词规则，不声称语义路由。出游需求加载 outing_plan、D01 / D02 和天气、场馆、费用流程；费用需求仅加载 budget_check、D02 与场馆、费用流程。模型提出流程内的工具请求，程序校验并实际执行。费用输出提供程序核算的三处总价和预算判断，模型摘要单独保留；不查天气，不推荐出游。

“帮我看看”不加载技能，模型只生成澄清问题，工具调用数为零。切换需求后使用独立轨迹。观察 Router 与澄清出口上的橙色标记：输入不明确时不能直接选技能。

## 第 11 页演示：Blackboard

真实轨迹依次展示 v0 初始化、天气发布 v1、场馆发布 v2、费用发布 v3、汇总发布 v4。调度器每轮检查缺失字段与角色就绪条件，完成角色不重复执行；天气、场馆、费用分别调用模型提出职责内的工具请求，程序执行并发布证据。费用角色只在场馆名单齐备后触发；汇总角色只在三类证据齐备后调用模型输出建议或无解，并经程序验收。

本例与外部模拟一样串行调度。橙色标记指向黑板和依赖角色，说明资料未齐时需要等待、发布要管理版本；没有模拟并发冲突或持久化恢复。

## 第 12 页演示：Graph / Workflow

真实轨迹保持 START → weather → catalog → indoor_filter / all_places → cost → validate → recommend / no_solution → END。工具节点由程序实际执行，天气分支与预算出口由显式代码决定。结果节点调用模型，以已有天气、场馆与完整费用生成回答，程序继续校验引用与结论；模型不会选择或新增图路径。

与模拟相比多了实际模型请求与验收记录，节点顺序和分支规则一致。橙色标记指向 catalog / validate 的预设分支：新路径需改图；本例没有检查点恢复。

## 现场展示的范围

| 展示方式 | 课堂可以声明的事实 |
| --- | --- |
| HTML“下一步演示” | 预写规则示意，不调用真实模型 |
| 本地服务“真实模型演示” | DeepSeek 主用 / OpenAI-Codex 备用，程序执行合成只读工具，提供逐步轨迹 |
| 模型聊天窗口与人工回填 | 真实模型生成，观察或角色消息由讲师提供 |
| 接好模型与工具的运行环境 | 模型真实决策、宿主真实执行合成只读工具，可检查调用日志 |

当前实现按需从 CCSwitch 读取模型凭据，仅交给本地客户端进程，不写入离线 HTML。设置请求超时和总调用上限，记录模型名称、输入条件、角色、工具调用及结束原因。网络或模型失败时明确切换到预录轨迹，不把回放呈现为现场调用。
